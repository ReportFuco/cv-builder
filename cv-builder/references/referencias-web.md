## 2. Fichas por referencia

### 01 · Enhancv: Data Analyst (EN)
- **Orden:** Encabezado (nombre, titular "Data Analyst | IoT Insights | Data Visualization", teléfono, correo, LinkedIn, ciudad) → Summary → Experience. En la columna derecha: Education → Languages → Projects → Key Achievements → Skills → Training/Courses → Interests.
- **Layout:** 2 columnas sin foto. Nombre en mayúsculas y negrita, titular en azul, empresa en azul. Fechas `MM/YYYY - Present` con íconos de calendario y ubicación. Idiomas con 5 puntos de nivel. Sans-serif. Títulos en mayúscula con línea.
- **Bullets:** verbo + acción + % de impacto.
  - "Automated data ingestion processes, cutting down manual data entry tasks by 60%."
  - "Led a team to design and implement data dashboards reducing report generation time by 40%."
  - "Refined data validation processes, contributing to a 25% improvement in data accuracy."
- **ATS:** aceptable. El texto es real y seleccionable, pero 2 columnas, íconos y puntos de nivel pueden desordenar el parseo. Algunos porcentajes son vagos ("enhanced engagement by 35%").
- **Para nuestro CV:** el **titular con 2-3 especialidades separadas por "|"**, la sección **Projects con link a GitHub en una línea** y "Training / Courses" con emisor y año. No tomar los puntos de idioma ni las métricas sin base.

### 02 · Resume Worded: Data Analyst (EN)
- **Orden:** Nombre + rol → Work Experience → Previous Experience (cargos antiguos en una línea cada uno). En la barra lateral: Contact → Skills (Hard Skills / Techniques / Tools and Software / Languages) → Education → Other (certificaciones).
- **Layout:** 2 columnas, barra lateral celeste, títulos en azul, sin foto. Bajo cada empresa va una **línea en cursiva que la describe** ("startup de edtech con 50+ empleados y $100M+ de ingresos").
- **Bullets:** cifras de volumen y alcance.
  - "Managed large datasets with 20K observations using regular expressions…"
  - "Created dashboards using SSRS and Tableau to display 30+ KPIs…"
  - "Improved … storage capacity from 25 to 60TB by optimizing the archival database structure."
- **ATS:** el propio sitio lo declara compatible con ATS. Los encabezados son estándar y no hay gráficos, pero la barra lateral es un riesgo menor.
- **Para nuestro CV:** la **descripción de una línea por empresa** (útil para explicar a un reclutador de tech una empresa que no conoce), **skills agrupadas por categoría** y **experiencia anterior compacta**.

### 03 · Overleaf: Jake's Resume (MIT)
- **Orden:** Encabezado centrado (nombre, teléfono, correo, LinkedIn, GitHub en una línea con "|") → Education → Experience → Projects → Technical Skills.
- **Layout:** 1 columna, serif (Computer Modern), sin color. Títulos en versalitas con regla horizontal. Cargo y fechas en la misma línea (fechas alineadas a la derecha), empresa y ciudad en cursiva debajo. Proyecto: `Nombre | stack en cursiva` y fechas a la derecha.
- **Bullets:** "Developed a REST API using FastAPI and PostgreSQL…", "Published plugin … gaining 2K+ downloads and an average 4.5/5-star review", "Contributed 50K+ lines of code…". Son técnicos y nombran el stack. Las métricas son de uso, no de negocio.
- **ATS:** muy alto. Una columna, texto puro, encabezados estándar. Es la plantilla de referencia en la comunidad dev.
- **Para nuestro CV:** la **grilla cargo/fechas a la derecha**, el **stack del proyecto en la línea del título** y **Technical Skills como "Categoría: lista"** (Languages, Frameworks, Developer Tools, Libraries). Es la base ideal para la variante "ATS pura".

### 04 · Kickresume: Python Developer (EN)
- **Orden:** Nombre + contacto → Profile → Work Experience → Education (incluye el colegio) → Skills (Languages, Computer Skills) → Strengths (hashtags) → Volunteering → Certificates.
- **Layout:** barra lateral negra con los títulos de sección alineados a la derecha. Círculo con iniciales en lugar de foto. Skills con **5 puntos de nivel**. Serif para el cuerpo.
- **Bullets:** casi todo funciones ("Developed web application back end components…"). Solo uno tiene métrica: "…achieved a 15% cost reduction within one year."
- **ATS:** medio-bajo. Los títulos en una columna aparte y los puntos de nivel no se leen bien, y las "Strengths" con # son relleno.
- **Para nuestro CV:** sirve como **contraejemplo**. No usar puntos ni barras de nivel (Get on Board y G-Talent lo desaconsejan), no poner el colegio y no listar más de 4 blandas.

### 05 · Teal: Business Intelligence Analyst (EN)
- **Orden:** Nombre + contacto en una línea con "•" → Resumen sin título → Work Experience → Skills & Competencies → Education → Courses / Certifications.
- **Layout:** 1 columna, sans-serif, títulos pequeños en mayúscula, fechas a la derecha y mucho blanco. Muy sobrio.
- **Bullets:** largos y con contexto, tecnología y resultado.
  - "Automated 17 manual reporting processes using Python and SQL, saving 23 hours weekly and eliminating data accuracy issues…"
  - "Developed interactive Power BI dashboards … increasing stakeholder data adoption by 65% within the first quarter."
  - "…migrating from legacy SQL Server to a cloud-based Databricks platform, cutting processing time by 76%…"
- **ATS:** alto. Una columna y encabezados estándar, aunque la lista de 14 competencias genéricas es excesiva.
- **Para nuestro CV:** es la **referencia de redacción** para el candidato, porque sus bullets de automatización con Python/SQL y de Power BI calzan con su experiencia. También la **línea de contacto única con separadores** y las **certificaciones con emisor y MM/AAAA**.

### 06 · Novorésumé: Data Analyst (EN), con la mejor guía del grupo
- **Orden (guía):** Nombre + titular ("Data Analyst, SQL and Power BI") + contacto → resumen de 2-3 líneas sin título → Work Experience (herramientas dentro de cada bullet) → Skills (lenguaje de consulta, lenguaje de programación, herramienta BI, data warehouse) → Certificates (los que tienen examen primero) → Education (capstone o tesis si usó datos reales) → opcionales: Key Achievements para proyectos de portafolio, Volunteer, Languages.
- **Layout del ejemplo:** 1 columna, títulos naranjos, franja gris con contacto, íconos y GitHub. "Technical (IT) Skills" agrupadas en tabla etiqueta/lista. Educación y certificados en 2 sub-columnas.
- **Fórmula de bullet (textual):** "Each bullet needs a verb, the tool, the size of the data or audience, and the result, in that order." También: "Give every number its base", es decir, poner el punto de partida y el de llegada.
  - "Rewrote the weekly fill-rate report in SQL and Python, cutting its run time from 6 hours to 25 minutes."
  - "Reported on about 40,000 online orders a week in Excel and SQL, and automated 9 manual reports to save the team 12 hours a week."
  - "Cut duplicate customer records from 8.2% to 0.6% across 1.4 million rows with SQL matching rules."
- **Cambio de carrera (aplica directo al candidato):** "If you are coming from operations, logistics, finance or sales, keep reverse-chronological order… keep the bullets where you already worked with numbers: inventory counts, forecasts, reconciliations or KPI reports." Proyectos de portafolio: 1-2, cada uno con dataset, tamaño, herramienta y hallazgo.
- **Largo:** 1 página. 2 páginas solo con 10+ años o liderazgo de equipo. Bullets: 3-4 en el cargo actual y 1-4 en los anteriores.
- **ATS:** alto. Además recomienda nombrar cada herramienta en Skills **y** en un bullet ("a keyword search finds it twice").
- **Para nuestro CV:** la **fórmula del bullet**, la **tabla de "qué contar"** (dashboards, automatización, calidad de datos, decisiones, solicitudes) y la regla del cambio de carrera.

### 07 · Enhancv ES: Analista de Datos (ES)
- **Orden:** Nombre + titular ("Analista de Datos | BI | MS Power Platform | SQL") + contacto → Summary → Experience → Education → Languages. En la barra lateral: foto → Key Achievements → Skills → Certification → Interests.
- **Layout:** 2 columnas con barra lateral azul oscuro y **foto**. Idiomas con puntos.
- **Bullets (ES):** "Diseñé reportes automatizados utilizando SQL, reduciendo el tiempo dedicado a informes manuales en un 60%." / "Apoyé en la digitalización de informes diarios, ahorrando al equipo más de 10 horas de trabajo semanales." Están en primera persona del pretérito, con verbo y métrica.
- **Defecto visible:** los **títulos quedaron en inglés** ("SUMMARY", "EXPERIENCE") en un CV en español, y los niveles de idioma dicen "Native/Advanced". Mezclar idiomas se ve descuidado.
- **ATS:** medio. Tiene barra lateral, foto y bloques de logros separados de la experiencia.
- **Para nuestro CV:** la **conjugación en primera persona del pretérito** para los bullets en español ("Automaticé…", "Reduje…"). Lección: **todas las etiquetas de la plantilla deben salir de un diccionario i18n** según el idioma del CV.

### 08 · Enhancv: Python Developer (EN)

### 10 · Portafolio en GitHub Pages (Jekyll + AcademicPages), data scientist con cambio de carrera
- **Estructura:** menú (CV/Resume · Portfolio · Talks · Podcast). Sidebar con foto, rol, ciudad, LinkedIn y GitHub. El "About Me" cuenta en 3 párrafos el giro desde marketing hacia datos como fortaleza: "a background that makes me a stronger collaborator".
- **Proyectos:** lista con título y una línea "qué predice/recomienda + dataset + librería" ("…using the Metro Interstate Traffic Volume data set and the TensorFlow package").
- **Para nuestro CV:** muestra cómo **contar el cambio de carrera como ventaja** (procesos/banca → datos) y que el **CV vive dentro del portafolio**. La skill podría generar el mismo JSON en una versión web.

### 11 · Portafolio en GitHub Pages: analista BI (SQL + Power BI + Python)
- **Ficha de proyecto:** 🚀 Objetivo → 🔧 Herramientas (con librerías: pandas, psycopg2, SQLAlchemy) → 📌 Flujo (Extract → Transform → Load → Analyze → Visualize) → 📈 Hallazgos clave (3) → 🔗 Repo + 📊 Dashboard → 📸 capturas.
- **Para nuestro CV:** esta estructura es la que debe tener **el README de cada repo** que el CV enlace. En el CV se resume en 1-2 líneas: problema → stack → resultado.

### 12 · README de perfil GitHub: analista en transición
- **Estructura:** párrafo de historia ("linguist turned data analyst… teaching myself SQL, Python, Power BI, and Tableau") → Projects and Guides (link al portafolio) → My Skills (4 capacidades) → My Tools agrupadas: "Databases: SQL (PostgreSQL, MySQL, MS SQL Server, Google BigQuery), Excel" / "Python: NumPy, Pandas" / "Visualisation: Power BI, …".
- **Para nuestro CV:** las **herramientas agrupadas por categoría con la variante exacta** (decir "SQL Server" y no solo "SQL"). Es sobrio, sin widgets.

### 13 · README de perfil GitHub: "Featured Projects"
- **Estructura:** titular ("Aspiring Data Analyst | Python | SQL | Power BI") → About me con emojis → Currently learning → Tech stack en badges → **Featured Projects** (título con emoji, stack y 3 bullets de qué hace) → Certifications → GitHub Stats.
- **Crítica:** los proyectos no tienen resultado ni métrica (solo "Interactive Dashboard"), y el README expone correo y link a Drive. Lección: en el CV **cada proyecto necesita un resultado** y los datos de contacto se controlan.
- **Para nuestro CV:** la idea de **elegir 3-4 repos destacados** (pinned) en lugar de listar todos.

## 3. Patrones comunes

**Orden de secciones** (para alguien con unos 3 años de experiencia, en cronología inversa):
1. Encabezado: nombre, **titular con rol objetivo + 2-3 herramientas** ("Analista de Datos | Python · SQL Server · Power BI"), una línea de contacto (ciudad, teléfono, correo, LinkedIn, GitHub, portafolio).
2. Resumen de 2-4 líneas, a veces sin título, con años de experiencia, dominio, stack y un logro con número.
3. Experiencia, del cargo más reciente al más antiguo. Cargo, empresa, ciudad, fechas a la derecha y 3-5 bullets en el cargo actual. Los cargos antiguos irrelevantes se compactan en una línea.
4. Proyectos (sube por encima de Educación si el candidato cambia de rol o es junior): nombre | stack | link, más 1-2 bullets con resultado.
5. Habilidades técnicas agrupadas por categoría.
6. Educación (incluido el estudio en curso con fecha esperada: "Ing. en Computación, en curso, egreso 2027").
7. Certificaciones y cursos con emisor y MM/AAAA.
8. Idiomas con nivel en texto (o MCER/certificado).
9. (Opcional) Voluntariado. Los intereses casi nunca aportan.

**Largo:** 1 página para menos de 10 años (Novorésumé, Enhancv, BioBio). Máximo 2 (Randstad, Get on Board, G-Talent).

**Foto:** 9 de 13 referencias no la usan. Solo las plantillas "de diseño" (Enhancv ES, Kickresume con iniciales) le hacen espacio. Las guías chilenas recientes la desaconsejan o la consideran opcional.

**Habilidades:** las plantillas ATS usan **listas por categoría** ("Lenguajes: Python, SQL (T-SQL)"). Las barras y los puntos aparecen solo en las plantillas de diseño, y Get on Board y G-Talent piden explícitamente no puntuarlas.

**Proyectos y GitHub:** formato `Nombre | stack` + fechas + 1-3 bullets + link corto (`github.com/usuario/repo`). GitHub va en el encabezado. En el portafolio, cada repo lleva una ficha Objetivo → Herramientas → Flujo → Hallazgos → Links.

**Fórmulas de bullet:**
- **Verbo + herramienta + volumen/alcance + resultado con base** (Novorésumé). Ejemplo: "Reescribí el reporte semanal de fill-rate en SQL y Python, bajando su ejecución de 6 h a 25 min."
- **Automaticé N procesos/reportes con X → ahorro de H horas/semana** (Teal, Resume Worded, Novorésumé). Es el bullet que más se repite en los roles objetivo.
- **Construí N dashboards en Power BI usados por U personas de A áreas → decisión o cambio** (Novorésumé, Teal).
- **Calidad de datos: de A % a B % en N filas** (Novorésumé).
- Para métricas confidenciales: usar rangos, porcentajes o volumen ("~40.000 operaciones/semana").
- Evitar porcentajes sin forma de medirse ("mejoró la colaboración un 50%").

**Estilo visual:** 1 color de acento (azul, granate, naranja o verde azulado), sans-serif legible, títulos de sección en mayúscula o versalitas con una línea fina, fechas alineadas a la derecha y mucho espacio en blanco.

## 5. Recomendaciones para la skill

### 5.1 Plantillas
1. **`ats-clasica` (por defecto):** 1 columna inspirada en Jake's Resume y Resume Worded Power BI. Un color de acento, sans-serif (Inter, Lato o Source Sans), títulos en versalitas o mayúscula con una línea fina y fechas alineadas a la derecha en una tabla CSS (grid/flex, no `<table>`). Sin íconos obligatorios (si se usan, con texto al lado). Sin barras de habilidad.
2. **`moderna` (opcional):** encabezado con franja de color y foto opcional, pero con el cuerpo igual en **una sola columna de lectura**. Nada de barra lateral que el ATS lea antes que la experiencia.
3. Controles de render: verificar que el PDF quede en **1 página** (avisar si se desborda), que el texto se pueda seleccionar y que el orden de lectura sea correcto (extraer el texto del PDF con PyMuPDF y compararlo con el orden esperado).
4. **i18n:** todas las etiquetas ("Experiencia", "Proyectos", "Presente/actualidad", meses) vienen de un diccionario `es`/`en`, así se evita el error de Enhancv ES.

### 5.3 Reglas que debería aplicar la skill (lint del CV)
- Cada bullet empieza con un verbo (en pretérito y primera persona en español: "Automaticé", "Reduje", "Construí") y tiene **herramienta y resultado**. Avisar si no hay número, y sugerir que el número tenga base ("de 6 h a 25 min").
- Cada herramienta de `habilidades` aparece en al menos un bullet o proyecto (consejo de Novorésumé: "keyword search finds it twice").
- 3-5 bullets en el cargo actual y 1-3 en los anteriores. Proyectos destacados: 2-3.
- Si `pais: CL`, no renderizar RUT, edad, estado civil ni dirección exacta salvo un override explícito.
- Para el candidato: aprovechar la regla del cambio de carrera. Poner en primer plano los bullets con números de operación (cobranza, inventario, KPIs, reportes automatizados) y subir **Proyectos** por encima de **Educación** cuando el rol objetivo sea dev o automatización.
- Generar dos salidas desde el mismo YAML: `es` (mercado chileno) y `en` (remoto, multinacional, Get on Board).
